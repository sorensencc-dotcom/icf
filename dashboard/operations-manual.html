1. System Overview and Topology

Iron Command Forge (ICF) serves as the primary operator console, telemetry matrix, and automation control plane across the zero-token local bot fleet. ICF consolidates observability across knowledge synthesis (KB-Sync), autonomous bot runners (IronBots), topic research mining (TRM), ledger accounting (IronLedger), and model headroom optimization.

2. Server Lifecycle & Supervisor Daemon

The ICF server runs as an elevated Node.js service binding to loopback host 127.0.0.1 on port 8080.

Manual Foreground Startup

To run the standalone server in the terminal:

cd C:\dev\icf
npm run start

Background Watchdog Probe

To verify server health and launch it silently if offline:

pwsh -NoProfile -File C:\dev\icf\scripts\ensure-dashboard-server.ps1

Zero-Downtime Daemon Restart

Elevated Task Security: Because the background process runs under Windows Task Scheduler with highest administrative privileges, standard user-level taskkill commands will fail with Access Denied.

To execute a clean daemon restart, write the sentinel trigger file and start the supervisor task:

New-Item -ItemType File -Path "C:\dev\.restart-trigger" -Force
Start-ScheduledTask -TaskPath "\Ironbots\" -TaskName "Daemon-Healer"

The daemon-healer-bot.mjs supervisor detects the trigger, terminates stale workers, launches a fresh daemon rooted at C:\dev\icf, and purges the trigger file.

4. Dual-Action Execution Engine

Buttons across ICF feature live dispatch capabilities backed by fallback clipboard copy.

Direct Execution Flow

  1. Clicking an actionable button invokes runAction(action, script, btn, fallbackCmd).
  2. Dispatches a POST /api/actions/run request containing the action and target script.
  3. The server verifies loopback origin (127.0.0.1), enforces the security whitelist, and spawns the background worker.
  4. Button transitions to Running... ⏳, followed by toast notification with the operating system PID: Process dispatched (PID: 12345).
  5. Button state updates to Triggered ✓.

Manual Copy Fallback

Hold the Shift key while clicking any button, or click buttons marked with terminal commands to copy shell syntax directly to the operating system clipboard.

6. Diagnostic & Runbook Procedures

Runbook A: Diagnose HTTP 500 or Unresponsive Dashboard

  1. Check listening ports: 
    Get-NetTCPConnection -LocalPort 8080
  2. Check server log for uncaught exceptions: 
    Get-Content C:\dev\icf\daemon.log -Tail 50
  3. Execute self-healing restart trigger: 
    New-Item -ItemType File -Path "C:\dev\.restart-trigger" -Force
Start-ScheduledTask -TaskPath "\Ironbots\" -TaskName "Daemon-Healer"

Runbook B: Remediate Broken Wikilinks in Tab 03

  1. Run wikilink validation: 
    cd C:\dev\kb-sync
npm run wiki:validate
  2. Run automated repair for missing stub targets: 
    npm run wiki:autoheal

Runbook C: Purge Browser and Backend Caches

Click the CLEAR CACHE button in the dashboard header. This empties browser localStorage, sessionStorage, dispatches POST /api/actions/clear-cache, and reloads the page with clean SSE telemetry.
